## Blocker 1 — Pine löscht aktive FVG-Zonen

Fundstelle: `Symbiose_Signal_System_v1.pine:303-309,322-328`.

Aktuell wird bei mehr als 30 FVG-Boxen die älteste Box blind entfernt. Das kann eine aktive, unmitigierte Zone löschen.

Soll:

- Drei Kerzen dienen nur zur Formation:
  - Bullish: `low > high[2]`
  - Bearish: `high < low[2]`
- Jede aktive Zone bleibt bis zu ihrer eigenen vollständigen Mitigation erhalten.
- Eine Speicher-/Anzeigegrenze darf ausschließlich bereits mitigierte Zonen entfernen.
- Alle parallelen Arrays müssen atomar und indexgleich bleiben.
- Falls alle Zonen aktiv sind, darf keine davon aufgrund einer Anzahlgrenze gelöscht werden.
- Pine-Plattformlimits beachten. Wenn die maximale Box-Anzahl technisch erreicht werden kann, muss das Verhalten sichtbar/fail-closed sein und darf keine aktive Zone fälschlich als mitigiert behandeln. Keine erfundene Strategie-Invaliderung.

TDD:

- Zuerst statischen/vertraglichen Test ergänzen, der die aktuelle blinde `array.shift`-Logik rot macht.
- Test muss mehr als 30 aktive Zonen abdecken oder strukturell beweisen, dass nur inaktive Indizes entfernt werden.
- Danach minimaler Pine-Fix.
- `tests/pine_static_check.py` und relevante Engine-/Paritätstests ausführen.

## Blocker 2 — korrupter State-GET liefert falsches 200 `{}`

Fundstelle: `bitget_relay.py:175-184` und GET-Handler für `/api/state`.

Aktuell degradiert `_load_shared_state()` beschädigtes oder nicht-objektförmiges JSON zu `{}`. Client deutet das als gültigen leeren Zustand.

Soll:

- Fehlende Datei bleibt legitimer leerer Initialzustand.
- Existierende korrupte, unlesbare oder nicht-objektförmige Datei ist ein Persistenzfehler.
- `GET /api/state` antwortet dann HTTP 500 mit `code: ERR_STATE_PERSIST`.
- Keine internen Pfade oder Exception-Details an Client senden.
- Ursprüngliche Datei/Bytes bleiben unverändert.
- POST-Legacy und Mutation bleiben ebenfalls fail-closed.
- Bestehende Aufrufer von `_load_shared_state()` vollständig verfolgen; Signatur kontrolliert anpassen.

TDD:

- Zuerst HTTP-Regressionstests für ungültiges JSON und gültiges JSON-Array als State-Datei schreiben.
- Beide müssen vor Fix rot sein, danach 500/`ERR_STATE_PERSIST` liefern und Bytes bewahren.
- Test für fehlende State-Datei muss weiterhin 200 mit leerem State belegen.

## Blocker 3 — irreführender Sync-Status

Fundstelle: `Symbiose_Dashboard.html:6371-6379`.

Aktuell setzt ein erfolgreicher Pull bei Overflow oder dauerhaft blockierter Mutation den Status auf `synchronisiere`, obwohl keine automatische Verarbeitung mehr läuft. Zusätzlich ist die Overflow-Prüfung durch die frühere `hasUnsyncedWork()`-Verzweigung teilweise unerreichbar.

Soll:

Status-Priorität nach jedem Pull:

1. `queueCorrupt` oder `queueOverflow` → `offline`, sichtbarer Text `nicht synchronisiert`.
2. dauerhaft blockierte Pending-Mutation → `offline`, sichtbarer Text `nicht synchronisiert`.
3. aktiv sendbare Pending-Mutation / laufender Retry → `bootstrap`, Text `synchronisiere`.
4. keine Arbeit → `synced`, Text `synchronisiert`.

- `hasUnsyncedWork()` darf nicht allein blockierte/overflow/corrupt Zustände als aktive Synchronisierung darstellen.
- Kein Busy-Loop.
- Pending-Intent bleibt persistent.

TDD:

- Zuerst Tests für Pull nach Queue-Overflow und Pull nach dauerhaft blockierter Mutation ergänzen.
- Vor Fix müssen sie an `synchronisiere` scheitern.
- Danach beide `nicht synchronisiert`/offline.
- Bestehender Test für normal sendbare Queue muss weiterhin `synchronisiere` oder nach ACK `synchronisiert` liefern.
