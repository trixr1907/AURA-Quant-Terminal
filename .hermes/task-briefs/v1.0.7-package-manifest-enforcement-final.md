## Belegter Blocker

Der normale Build nutzt `collect_files()` und erzeugt ein sauberes Paket. Aber `build_archive(files, output)` akzeptiert direkt injizierte, normale Dateien innerhalb von `ROOT`, obwohl diese nicht aus der aufgelösten `MANIFEST`-Allowlist stammen.

Reproduktion des unabhängigen Reviews:

- Manifest erlaubt nur `data/bitget_usdt_futures_universe.json`.
- `build_archive(["data/secret_fixture.json"], ...)` akzeptiert die unbekannte Datei.
- Resultat: `DIRECT_UNKNOWN_DATA_ACCEPTED`.

Das verletzt den fail-closed Allowlist-Vertrag.

## Gewünschter Vertrag

1. `build_archive(files, output)` darf nur normalisierte Dateien akzeptieren, die auch durch die aktuelle `MANIFEST` plus bestehende Filter/Path-/Symlink-/Runtime-State-Regeln aufgelöst werden.
2. Ein direkt injizierter Pfad außerhalb dieser aufgelösten Allowlist muss `ValueError` auslösen — auch wenn er innerhalb `ROOT` liegt, reguläre Datei ist und einen harmlosen Namen hat.
3. Das gilt besonders für unbekannte Dateien unter `data/`, aber generisch für jeden nicht manifestierten Pfad.
4. Verzeichniseinträge in `MANIFEST` dürfen weiterhin deren sicher aufgelöste erlaubte Kinder zulassen.
5. Bestehende Guards behalten:
   - nur explizite statische Data-Datei im echten Manifest
   - komplette `aura_shared_state`-Familie blockiert
   - kein absoluter Pfad, `..`, Backslash/Laufwerkspräfix
   - keine Symlink-Datei, kein Symlink-Verzeichnis/Elternsegment
6. Keine echten Runtime-State- oder Secret-Dateien lesen. Tests nur in temporären Verzeichnissen mit harmlosen Sentinels.

## TDD — RED vor GREEN

4. Bereits bestehende Tests für Runtime-State, Traversal, absolute Pfade und Symlinks bleiben grün.

Gezielten Test vor Produktionscode ausführen und erwartetes RED dokumentieren. Danach minimaler Fix und GREEN.

## Implementationshinweis

MANIFEST-Vertrag zentral auflösen. Keine rekursive Endlosschleife zwischen `collect_files()` und `build_archive()`. Mögliches Muster:

- interne Funktion löst MANIFEST sicher zu erlaubten relativen Dateien auf
- `collect_files()` nutzt diese Funktion
- `build_archive()` bildet daraus ein Set und fordert `requested ⊆ allowed`

TOCTOU soweit im Rahmen dieses Builders sinnvoll vermeiden: alle angeforderten Dateien direkt vor ZIP-Schreiben erneut mit bestehenden Safety-Regeln validieren.
