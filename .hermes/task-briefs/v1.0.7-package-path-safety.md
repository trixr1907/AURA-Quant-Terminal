## Belegter Blocker

Der aktuelle Builder schließt bekannten Runtime-State aus, validiert aber nicht, dass jede Paketquelle tatsächlich innerhalb `ROOT` liegt:

- `build_archive(["../secret.txt"], ...)` kann Dateien außerhalb des Projekts aufnehmen.
- absolute Pfade können `ROOT / rel` umgehen.
- Symlinks in rekursiv erlaubten Verzeichnissen können auf externe Dateien zeigen und deren Inhalte ins ZIP übernehmen.

Das aktuelle ZIP ist sauber. Blocker betrifft den Builder-Vertrag für reproduzierbare, fail-closed Releases.

## Soll

1. Jeder Manifest-Eintrag und jede aufgelöste Paketdatei bleibt lexikalisch und nach Auflösung innerhalb `ROOT`.
2. Verboten:
   - absolute Pfade,
   - `..`-Traversal,
   - Pfade, deren `resolve()` außerhalb `ROOT.resolve()` liegt,
   - Symlinks als Datei oder Verzeichnis,
   - Dateien unter einem Symlink-Elternsegment.
3. Rekursive Verzeichnissuche darf Symlink-Verzeichnissen nicht folgen und Symlink-Dateien nicht aufnehmen.
4. `build_archive()` revalidiert jede übergebene Dateiliste unabhängig von `collect_files()` und wirft vor dem Schreiben eines verbotenen Eintrags kontrolliert `ValueError`.
5. ZIP-Arcnames sind ausschließlich normalisierte relative POSIX-Pfade ohne führenden Slash, `..`, Backslash-Traversal oder Laufwerkspräfix.
6. Normale erlaubte Dateien und Verzeichnisse werden weiter paketiert.
7. Bestehender Ausschluss `aura_shared_state.json` bleibt vollständig erhalten.

## TDD — einzelne vertikale Zyklen

Zuerst Regressionstests in `tests/test_release_sync.py` ergänzen und jeweils RED beobachten:

1. Direkter `../outside.txt`-Eintrag wird von `build_archive()` abgelehnt.
2. Absoluter externer Pfad wird abgelehnt.
3. Symlink-Datei unter einem erlaubten `data/`-Verzeichnis wird von `collect_files()` ausgeschlossen und von `build_archive()` bei manipulierter Liste abgelehnt.
4. Optional: Symlink-Verzeichnis unter `data/` auf externes Verzeichnis wird weder traversiert noch paketiert.
5. Normale Datei `data/market_fixture.json` bleibt erlaubt.

Tests müssen ausschließlich temporäre Dateien verwenden. Keine echten `/etc/*`, Secrets oder Nutzerdateien lesen.
